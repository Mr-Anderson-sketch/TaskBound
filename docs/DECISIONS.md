# Decisions

One line each, newest at the bottom. Rationale follows the dash.

- 2026-09-14 Stay on Electron, upgrade in place to the current major — only stack here that gives always-on-top, click-through, global hotkeys, tray, and per-monitor work areas without native modules.
- 2026-09-14 Retire the `pwa/` tree — a focus strip cannot exist in a browser; two codebases halve the effort on the one that matters. It remains in git history.
- 2026-09-14 Timer stays first-class; score becomes an opt-in setting (off by default); the three-minute nag popup is removed — the mission names non-intrusiveness as the key factor.
- 2026-09-14 Store moves to the main process; renderers are views — one source of truth for strip, main window, capture, and tray; fixes the two-tick-source drift in the old renderer store.
- 2026-09-14 Pure `src/core/` package with no Electron imports — makes parser, recurrence, undo, migration, and timer math unit-testable with Vitest.
- 2026-09-14 Schema v2 with an explicit `schemaVersion` and a migrator; legacy `state.json` is imported, copied to `backups/`, and never deleted — guardrail on user data.
- 2026-09-14 Work on branch `feat/focus-first`; no pushes to origin unless asked — the brief says branch and commit; pushing is outward-facing.
- 2026-09-14 Cloud sync proposal, not built: user-chosen sync folder (OneDrive/Dropbox/Syncthing) holding `data.json`, last-writer-wins with a conflict copy — free and privacy-safe; revisit after v1 ships.
- 2026-09-14 Installer ships unsigned — code signing needs a paid certificate; question deferred to the final report.
- 2026-09-14 Start-on-login is an opt-in toggle, default off, implemented with Electron's login-item API (a per-user registry Run entry) — mild, reversible, and standard for tray apps; not treated as a broad OS permission.
- 2026-09-14 macOS is a first-class target (owner direction), Windows 11 remains primary and the only platform verifiable on the build machine — strip uses an NSPanel-type window on macOS; a macOS "menu bar mode" ships; DMG packaging configured; a macOS release checklist replaces automated verification there.
- 2026-09-14 Hotkey defaults use only non-character keys (`Ctrl+Alt+Space`, `Ctrl+Alt+Shift+Space`, `Ctrl+Alt+Enter`, `Ctrl+Alt+Shift+Enter`, `Ctrl+Alt+Backspace`) — AltGr never maps those, so the same table works on every layout and on macOS as Control+Option.
- 2026-09-14 The gstack design mockup tool is not used — it calls the OpenAI image API, which needs a billed key. Strip and window variants are hand-written HTML at true pixel size instead.
- 2026-09-14 Implementation will be executed by Sonnet-model subagents from per-slice briefs in PLAN.md, with the lead reviewing each slice (owner direction).
- 2026-09-14 Store never ticks; timer expiry is a single armed timeout; renderers derive display time locally — removes the 1 Hz full-snapshot broadcast and the two-tick-source drift from the old code.
- 2026-09-14 Undo is a ring of 50 immutable previous states (immer structural sharing), not inverse actions — recurrence spawns and timer stops have no clean inverse.
- 2026-09-14 One optional FFI module (`koffi`) on Windows only, lazily loaded, every feature gated with fallback — AppBar space reservation and fullscreen detection have no first-party Electron API; the app is complete without it.
- 2026-09-14 Default dock edge is bottom — a top strip covers browser tab bars; bottom sits above the taskbar like a second taskbar.
- 2026-09-14 Strip construction: variant A "Label" (flat backplate flush to the edge, 6 px free corners, 2 px progress hairline) — B "Ruled" costs 2 px and its timer column reads as a table; C "Capsule" floats 8 px off the edge and never reads as part of the OS.
- 2026-09-14 Planner layout: variant A three columns (rail, list, detail) — the current task's timer and notes are visible without a click, which is the product's whole premise; B two-pane is kept as the layout under 900 px width.
- 2026-09-14 Typography: IBM Plex Sans (UI), IBM Plex Mono (timers, counts), Instrument Serif (view titles, onboarding) — bundled via @fontsource so the app never loads fonts from the network; Plex is built for small UI sizes and has tabular figures; Instrument Serif gives the stationery warmth without touching the strip.
- 2026-09-14 Themes: Ledger (default), Kraft, Phosphor, Slate, each light and dark, tokens in `src/renderer/theme/themes.json`, CSS generated, AA verified by `scripts/check-contrast.mjs` (text ≥ 7:1, secondary ≥ 4.5:1) — physical-object inspiration per the brief; no gradients, no glass.
- 2026-09-14 Dependencies added (setup): `zod` (one schema for IPC, file, settings validation), `immer` (pure reducers with structural sharing; undo ring stays cheap), `date-fns` (local calendar math incl. month-end clamping; no tz addon), `@tanstack/react-virtual` (500-task lists), `@fontsource/ibm-plex-sans|mono`, `@fontsource/instrument-serif` (bundled fonts, no network), `vitest` + `fast-check` (unit and property tests), `@playwright/test` (Electron e2e), `koffi` as optional (Windows AppBar/fullscreen, gated). Rejected: `chrono-node` (heavy, non-deterministic parsing), `electron-store` (sync writes, no rotation/recovery).
- 2026-09-14 `fs-extra` and `uuid` stay until Slice 1 deletes the old renderer and state manager that use them — removing them now would break the build the setup promises to keep green.
- 2026-09-14 Electron upgraded 28 → 44 in place; the old app builds and passes the smoke test on it. Note: npm did not run Electron's own binary download during install on this machine; `node node_modules/electron/install.js` fixes it and is documented in README.
- 2026-09-15 Tailwind removed (`tailwindcss`, `autoprefixer`, `tailwind.config.cjs`, `postcss.config.cjs`): every new component's CSS is ported plain from `docs/design/preview.html` into `src/renderer/styles/app.css` — the design system is small (one stylesheet, four themes via CSS custom properties) and gains nothing from a utility framework.
- 2026-09-15 `uuid` removed; new task ids are generated in the renderer with `crypto.randomUUID()` (available in the sandboxed renderer) and validated by the existing zod `IdSchema` in main before they touch the Store — no dependency needed for a one-line browser API.
- 2026-09-15 `fs-extra` removed along with `src/main/stateManager.ts`, `src/shared/ipc-legacy.ts`, `src/shared/types.ts`, `src/shared/stateHelpers.ts`, and the legacy `window.electronAPI` bridge in `preload.ts` — the old renderer that used them is deleted in this slice; `src/main/persist.ts` already uses plain `node:fs/promises`.
- 2026-09-15 `vitest.config.ts`'s `environmentMatchGlobs` (routing `tests/renderer/**` to a `jsdom` environment) is removed rather than adding `jsdom` as a dependency: every unit test in this slice, including `tests/renderer/format.test.ts`, is pure logic with no DOM dependency, so the base `node` environment covers it. A future slice that needs to unit-test actual DOM/React behavior (as opposed to e2e, which already exercises the real renderer) should re-add `environment: 'jsdom'` scoped to whatever needs it, with `jsdom` as a real devDependency at that point.
- 2026-09-15 `.strip`/`.panel` are sized `width: 100%` (the window's own content width), not `width: max-content` — DESIGN.md's strip has a fixed, user-resizable width with the title flexing/ellipsizing inside it; a content-hugging width fed back through the `ResizeObserver → strip:reportSize → redock` loop shrank the window to the empty-state text's natural width (290px) instead of the configured 420px on every launch. `.pill` keeps `width: max-content` (capped at 240px) — DESIGN.md specifies the collapsed pill as content-hugging, unlike the full strip.
- 2026-09-15 Known Windows platform limitation (not fixed; `src/main/windows/strip.ts` is out of scope — "do not modify strip.ts"): Windows enforces a minimum frameless-`BrowserWindow` height of ~39 DIP regardless of the requested bounds, so the bottom-docked strip (32 px content) ends up in a 39 px window with a ~7 px transparent gap below the visible strip instead of sitting flush against the screen edge. `e2e/focus.spec.ts`'s bounds assertions carry an explicit `OS_MIN_HEIGHT_SLACK` for this, matching the `bounds.height <= 40` (not `<= 32`) ceiling already specified in the task brief. A real fix belongs in `strip.ts`'s `redock`/`handleReportedSize`, re-reading the window's actual post-`setBounds` height and compensating `y` for any OS-imposed delta.
- 2026-09-15 `WindowCommands.dataExport`/`dataChooseDir` stubs return `{}` rather than `{ error: 'not yet' }` (`data:import`'s stub does use `{ error: 'not yet' }`) — `error` isn't a field of `InvokeMap`'s `data:export`/`data:chooseDir` return types (only `data:import`'s), so returning it there would be a type error against an interface this task doesn't own; `{}` is a valid `{ path?: string }`/`{ dir?: string }` meaning "did nothing, produced nothing," which is the same stub behavior the brief asked for. Real implementations land in Slice 5.
- 2026-09-15 The hover panel's 5 s "Completed X · Undo" row is wired to `Snapshot.lastUndoLabel` exactly as the brief specifies, but `src/main/store.ts` (built in an earlier task, not modified here) only sets that field inside `undo()`/`redo()`, not on a plain `dispatch()` — so today the row actually appears after an undo/redo (offering to undo *that*, i.e. a redo), not immediately after every completion (the strip's own 1.2 s "Undo" chip already covers that case for the current task specifically). Making the row appear right after any undoable dispatch would need `Store.dispatch` to also set `lastUndoLabel`, which is out of this task's scope (store.ts is a "read their exports" file). No e2e spec exercises this row. **Superseded by fix round 1, C2 below.**
- 2026-09-15 (fix round 1, C2) `Snapshot.lastUndoLabel` replaced with `lastUndo?: { label, rev }`, and `Store.dispatch` now sets it on every dispatch that pushes an undo entry (not just `undo()`/`redo()`, which now CLEAR it) — was permitted to modify `store.ts`/`shared/ipc.ts` for this specific controller ruling. Fixes the previous entry's gap: the panel's undo row now appears after a normal completion, keyed off `rev` (not `label`, so two same-labelled actions in a row still re-trigger it) rather than after an explicit undo.
- 2026-09-15 (fix round 1, C1) `src/main/windows/strip.ts` was permitted to be modified for this controller ruling only. Root cause confirmed by the controller: a transparent frameless `BrowserWindow` on Windows cannot be shorter than ~39 DIP no matter what height is requested (not fixable from the renderer side, which is why the earlier "known Windows platform limitation" entry above called it out of scope). Fix: `StripWindow` now re-reads the actual post-`setBounds` height and re-anchors `y` so the requested content still sits flush against the docked edge inside the work area (never past it), and (win32 only) calls `win.setShape()` to clip hit-testing/paint down to the requested content rect — Electron transparent windows otherwise still capture clicks in the extra, invisible area. The renderer aligns content to the edge via `body[data-route="strip"][data-edge]`'s flex `justify-content`, driven by `settings.strip.edge`. `e2e/focus.spec.ts`'s `OS_MIN_HEIGHT_SLACK` is removed; it now asserts exact edge flush (`bounds.y + bounds.height === workArea.y + workArea.height`) and the applied shape via `globalThis.__tb.strip.lastShape`.
- 2026-09-15 (fix round 1, finding 12) Removed `app.hide()` from `PaletteWindow.hide()`'s macOS path — it hides EVERY window of the app, including the always-on-top strip, not just the palette. Known gap: focus does not automatically return to the previously-active app after quick capture on macOS (`docs/RELEASE-CHECKLIST.md` M15); revisit with a macOS-specific "restore previous app focus" API in Slice 6.
- 2026-09-15 (fix round 1, finding 18) `postcss` (the npm package, not just its config file) was removed from devDependencies along with Tailwind — no PostCSS plugin runs anymore since every stylesheet is plain CSS Vite handles natively.
- 2026-09-15 (Task 2.2) Live-parsed capture behaviour lives in a new pure module, `src/renderer/palette/captureModel.ts` (`chipsFor`/`isQuoted`/`quoteInput`/`splitPastedLines`/`actionsFor`), unit-tested at `tests/renderer/captureModel.test.ts` in the existing plain-`node` Vitest environment — `@testing-library/react` and `jsdom` were NOT added; `Capture.tsx` stays a thin controlled-input wrapper verified by `e2e/capture.spec.ts` instead.
- 2026-09-15 (Task 2.3) `DayRecord` gains an optional `rolloverAppliedAt` (types.ts + strict schema) so `day/rollover` can be idempotent per calendar date: a record that already carries it makes a repeat dispatch for that exact date a pure no-op (same `Data` reference), which is what lets `Clock.start()` dispatch rollover unconditionally on every launch/resume/unlock without ever double-counting a day's rolled-over tasks.
- 2026-09-15 (Task 2.3) Added `palette:reportSize` (renderer -> main IPC, zod-validated `height` 60..640) so `PaletteWindow` can resize to fit each mode's sheet: capture stays a fixed 132 px, but "Plan today"/"Close the day" size to their real content (the plan sheet's own candidate list scrolls internally past ~300 px so the reported height never needs to exceed the design's 480 px cap). Reported via a `ResizeObserver` on the palette's root element in `PaletteApp.tsx`, applied via `PaletteWindow.setContentHeight`, which keeps the window's `x` and top `y` fixed while its height changes.
- 2026-09-15 (Task 4.2) `usePlannerKeys` auto-selects the first visible row whenever a view has rows and nothing is selected (on load and right after switching views), rather than waiting for the first `j`/`k` press to do it — reconciles the addendum's literal "selects the first row when nothing is selected" wording (which, read as "only the first keypress selects row 0," would make `j j` land on row 1, not row 2) with its own required e2e outcome ("`j` `j` `Space` -> the third task is done"): with a pre-selected row 0, two subsequent `j` presses land on row 2 as required.
- 2026-09-15 (Task 4.2) `Shift+↑/↓` reorders across every section EXCEPT one keyed `'done'`, not just the selected row's own section — Today's "Current" and "Up next" are one `order`-sorted sequence split only for display (`todayTasks`'s `current`/`upNext` are one sorted array sliced), so scoping to a single section would make `Shift+Up` on the sole "Up next" row a no-op instead of swapping it with "Current". "Done" is excluded (sorted by `completedAt`, not `order`) and Upcoming is blocked outright (date-grouped) per the addendum.
- 2026-09-15 (Task 4.2) The command palette's "Add a task" clicks `.tb .cap-trigger` (`document.querySelector`) instead of `TitleBar.tsx` exposing an imperative open method — `TitleBar.tsx` is outside this task's file scope (addendum ruling 8 lists `PlannerApp.tsx`/`TaskList.tsx`/`TaskRow.tsx` plus the new files only), and its existing trigger button's own `onClick={() => setActive(true)}` already does exactly what's needed.
- 2026-09-15 (Task 4.2) `task/edit`'s patch fields that can be explicitly cleared (`due`, `notes`, `recurrence`) use `'key' in patch` rather than `patch.key !== undefined`, per the addendum. Confirmed this survives the renderer -> main hop: `ipcRenderer.invoke` (preload.ts) uses Electron's structured-clone-based serialisation, which — unlike `JSON.stringify` — preserves an own property whose value is `undefined`, and zod's `.optional()` (schema.ts) likewise keeps the key present with an `undefined` value rather than dropping it (verified directly against the installed zod version, not assumed).
- 2026-09-15 (Task 7.1, pulled forward from Slice 8) `koffi` usage: optional (already an optional dependency, see the setup-slice line above), loaded lazily via dynamic `import('koffi')` only on `process.platform === 'win32'`, and every capability it unlocks (`capabilities.appBar`/`capabilities.fullscreenDetect` in every `Snapshot`) is gated behind whether `src/main/win32/index.ts`'s `loadWin32()` actually succeeded — the app runs unchanged (both capabilities false) on macOS/Linux, when koffi's optional native module failed to install, or if any single Win32 function fails to bind. Window handles (HWND/HMONITOR) are represented as plain `uintptr_t`/`bigint` values end-to-end, never koffi's own pointer type — see `src/main/win32/geometry.ts`'s `hwndValue` doc comment: this app only ever passes these handles around and compares them, never dereferences them, and Electron's `BrowserWindow.getNativeWindowHandle()` returns the raw handle bytes directly (not a pointer to them), so decoding those bytes into an integer and marshalling every "pointer" as a same-width integer sidesteps real ambiguity in how koffi would otherwise treat a Buffer passed for a pointer-typed parameter (as pointing AT the buffer's own bytes, not reading them as an address).
- 2026-09-15 (Task 7.1) `appbar.ts`'s `reserve()` re-derives the anchor edge after `ABM_QUERYPOS` before calling `ABM_SETPOS` (bottom edge: recompute `top` from the QUERYPOS-adjusted `bottom`; top edge: recompute `bottom` from the adjusted `top`), restoring the originally-requested height. Verified live on the dev machine: without this step, requesting a bottom-docked rect flush to the physical screen edge (as `appBarRect` does) overlaps the existing taskbar's own AppBar registration, and `ABM_QUERYPOS` only moves the FAR edge (`bottom`, here) up to avoid it — passing that straight to `ABM_SETPOS` committed an inverted rect (`top > bottom`) and the reservation silently did nothing (`workArea` never shrank). This is the standard two-step AppBar dance from Microsoft's own sample code, not documented in koffi's own docs (which don't cover the AppBar API at all) — found by instrumenting `SHAppBarMessage`'s real return values and `rc` contents against the actual Windows AppBar API on this machine, then fixed and re-verified the same way (`e2e/win32.spec.ts`'s reserveSpace test now passes for real, confirmed against `[System.Windows.Forms.Screen]::PrimaryScreen.WorkingArea` before/after/restored).
- 2026-09-15 (Task 7.1) The AppBar reservation's `uCallbackMessage` (`APPBARDATA.uCallbackMessage`) is a fixed sentinel above `WM_APP`, not a real id from `RegisterWindowMessageW` (not in this task's koffi binding list) — v1 does not hook into a window message loop to handle `ABN_*` notifications (another AppBar registering, taskbar auto-hide state changes); the app only needs the static space reservation, so unhandled/undelivered notifications are harmless. Documented in `src/main/win32/appbar.ts`.
- 2026-09-15 (Task 7.1) While an AppBar reservation is active, `StripWindow` docks against the GRANTED rect (`src/main/windows/displays.ts`'s `dockedEdgeY`) instead of `workArea` on the docked edge — `workArea` is already shrunk by our own reservation, so docking against it on every redock would push the strip inward again and again (the reservation "chasing" its own shrinking work area). The granted rect is only used while docking onto the SAME display it was granted for (tracked by display id); a 60 Hz drag tick never re-reserves (far too hot a path for `SHAppBarMessage`) and instead relies on the display's already-shrunk `workArea` (a legitimate proxy once a reservation is live and stable on that display) until `endDrag()` re-syncs.
- 2026-09-15 (Task 7.1) `ownHwnds()` (main.ts's fullscreen-watcher wiring) only includes windows this app itself owns via `BrowserWindow.fromWebContents` over `liveWebContents()` (strip, palette, planner) — no change to `src/main/windows/{palette,planner}.ts` was needed (out of this task's file scope) since both already expose a `webContents` getter `main.ts` already used for broadcasting.
- 2026-09-15 (Task 6.1) macOS menu bar mode's status item title is `<truncated task title, 28 chars default>` alone, or with `'  ' + fmtClock(remaining ?? elapsed)` appended while the timer runs — two spaces (not one) so the clock doesn't read as glued to the title in the system font; composed by the pure `src/main/trayTitle.ts` and pushed to `Tray.setTitle` at most once a second (an interval armed only while a timer runs) plus on every store change, never faster.
- 2026-09-15 (Task 6.2) `.github/workflows/build.yml`'s matrix (windows-latest/macos-latest; `npm ci && npm test && npm run build`) triggers on `workflow_dispatch` only, not `push`/`pull_request` — GitHub Actions minutes are metered on this private repo and the owner has not yet decided whether every push should spend them; flipping it on later needs only an added trigger, nothing else in the file.
